## 5. 머신러닝 기법 비교 (scripts/05_ml_experiments.py) — 잡음 1배 (괄호: 잡음 2배)

1. **특징 선택 (순차 전진 선택, nested CV)**
   - 올바른 방법 정확도: 1개 59.7% → 2개 91.6% → **3개 98.1%** → 4개 99.5% (잡음 2배: 53.3 → 88.6 → 96.5 → 98.2%)
   - 세 fold 모두 첫 번째로 **T4a**, 세 번째로 **T5d** 선택 (잡음 2배에서는 T4b → TmY4/T4c → T5d)
   - 누수 있는 선택(테스트 정답을 보고)과의 차이: 최대 +2.5%p (유형 2개일 때 91.6% vs 94.1%; 잡음 2배 +1.3%p). 실제 데이터는 쉬워서 차이가 작다
2. **채널 수 맞춘 비교** (신호 A에서 무작위 4개 유형 200번)
   - 무작위 4개 중앙값 68.6%, B4 84.1% → B4가 무작위 조합의 80%보다 낫다 (잡음 2배: 중앙값 55.8% vs B4 54.2%, 47%보다 낫다)
   - 잘 고른 4개(특징 선택)는 99.5%
3. **특징 추출**: 시간 영역 vs PSD vs 둘 다
   - A 99.9 / 75.1 / 99.3%, B4 84.1 / 68.4 / 86.0%, B1 40.3 / 14.4 / 38.4%
4. **분류기 (nested CV로 C, k 선택)**: 로지스틱 회귀 / 선형 SVM / K-NN
   - A 99.9 / 98.5 / 99.2%, B4 84.6 / 82.1 / 83.3%, B1 41.0 / 38.8 / 45.2%
5. **검증 방법과 누수** (B4): 속도 기준 84.1%, 전체 데이터로 정규화 84.2%, 무작위 5-fold 85.5%
6. **가짜 정답(조건 단위로 방향 정답을 섞음)에서 특징 선택**

## 7. 설계에서 바꾼 점과 이유

1. **세포 유형 65개**: 생물학적 세포 유형은 64개이고, flyvis 모델은 CT1을 CT1(Lo1)·CT1(M10) 두 구획으로 나눠 65개로 다룬다. 신호 A의 65채널은 이 모델 내부 유형 기준.
2. **녹화 저장 형식**: "모든 뉴런 전압"을 저장하면 48조건에 약 4 GB. 대신 (세포 유형 65 × 구역 4)별 합과 뉴런 수를 저장했다. 신호 A·B4·B1이 모두 이 값에서 정확히 계산되므로 분석 정보는 잃지 않는다. 예시 조건 1개만 전체 뉴런을 저장(애니메이션용). 저장은 100 Hz(시뮬레이션은 200 Hz, 이웃 프레임 평균).
3. **막대 자극 크기**: flyvis 기본 막대(높이 9, 이동 ±10)는 눈 중앙만 지나가서 4구역 비교가 안 된다. 높이 80, 이동 ±35로 늘렸다.
4. **자극 렌더링**: MovingBar로 16개를 그리면 약 22분. flyvis 렌더링 함수(HexEye.render_offset_bars)로 밝은 막대 4방향만 그리고, 대칭(a+180° = 위치 순서 뒤집기, 어두운 막대 = 1 − 밝은 막대)으로 나머지를 만들었다. 실제 180° 렌더링과의 최대 차이 0.002로 확인.
5. **기준선 보정**: 막대가 나오기 전 1초 평균을 채널마다 뺐다(샘플 안에서만 계산하므로 누수 없음).
6. **재현 속도 1개**: 50개 모델을 모두 돌리려고 속도는 19 하나만 썼다(튜토리얼 기본은 6개).
7. **재현 그림**: 상위 10개를 평균하면 서로 다른 해가 섞여 곡선이 뭉개져서, 최고 모델(굵은 선) + 상위 10개 각각(옅은 선)으로 그렸다.
8. **누수 시연 추가 (5-6)**: 실제 데이터에서는 누수 효과가 작게 나와서(검증 방법 +1.4%p, 특징 선택 +2.5%p), 정답을 섞은 데이터로 누수가 "없는 성능"을 만들어 내는 것을 보였다.
9. **분류기 비교에 선형 SVM 추가**: CLAUDE.md 5단계 4번의 "필요하면 선형 SVM".

## 8. 안 된 것과 이유

- **flyvis `peak_responses`의 상위 모델 평균 곡선**: 정류(음수→0) 뒤 최댓값이라 일부 모델은 모든 방향에서 0에 가까워, 평균을 내면 방향성이 사라졌다. 기준선을 뺀 측정으로 바꿔도 모델별 정답 수는 거의 같아서(평균 3.8 → 4.0개) 측정 방법 문제가 아니라 모델 간 다양성으로 판단, 평균 대신 각각 그렸다.
- **MovingBar 병렬 렌더링**: 4개 동시 실행 시 메모리 부족으로 강제 종료(종료 코드 −9). 2개씩 실행으로 해결.
- **UMAP 군집 분석**: 공식 데이터(results_umap_and_clustering)는 받아 두었지만 발표 범위(머신러닝 파이프라인 중심)에서 빠져 분석하지 않았다.
